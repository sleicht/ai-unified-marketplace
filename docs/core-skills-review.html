R4 · Implemented · Contract review complete

Reverse and forward skills now share the FR contract.

The forward skill requires FR tables with IDs, user stories, priorities and statuses. The diagram skill requires each UC to trace to an FR.

A new reverse-engineered catalogue can therefore leave nothing concrete for that traceability check to resolve.

Implemented change

  • Requires FR IDs, diagram-comment mappings and corresponding UC Requirements links.
  • Records source evidence and uncertainty; unknown priority is To confirm, with no invented approval or NFR thresholds.
  • Keeps NFR/constraint table headers when no rows are evidenced and records the gap in Requirements Notes.

R5 · Implemented · Identity and reconciliation rules

Updates now reconcile identity and downstream references.

The core skills now read existing artefacts, preserve unaffected content and IDs, allocate new IDs above existing ones, and report consumers outside the authorised scope.

Original risk

A new goal changes the order.

An existing UC-004 can be reassigned during regrouping by actor or importance. A renamed diagram label can produce a new filename while TC links still point to the old one.

The business-rule contract adds a real constraint: rules are numbered without gaps, and the bundled Studio format says they are positional.

Implemented update contract
  1. Read existing output first; match by ID and business meaning.
  2. Keep existing FR, UC and TC IDs. Allocate new IDs without renumbering other items.
  3. Preserve unaffected content; report removed or renamed items and affected links.
  4. When BR renumbering is required, produce an old → new mapping and repair authorised references; report consumers outside the task scope.
Verified: the TC update exercise preserved its ID and links. UC rename and BR old → new mappings are explicit contract rules and fixture criteria; those cases were not separately run end to end.

R7 · Fixed · External-install tests passed

Resolve the skill and the project independently.

The skill instructions now resolve the installed validator and target project independently, then pass only the explicit files created or updated by the task.

Original instruction pattern
python3 scripts/validate_use_case.py \
  --strict docs/use_cases/UC-*.md

Running from the project usually misses the bundled script. Running from the skill directory usually misses the project docs. The wildcard also selects unrelated UCs.

Implemented behaviour
  • Resolve the installed script to an absolute path.
  • Resolve the selected project/service docs separately.
  • Pass an explicit, quoted list of files created or updated by this task.
  • End with the output path, checks and unresolved dependencies, so the next chat can work from files.
Verified: CLI tests copied the validator to a separate installation and ran from both project root and billing service. Paths contained spaces; one selected UC passed and an unrelated invalid UC stayed unchanged.

R8 · Implemented · Lifecycle semantics aligned

States and uncertainty now have explicit meanings.

Language alignment

One meaning in both languages.

  • Deferred ↔ Zurückgestellt.
  • Rejected ↔ Abgelehnt.
  • Superseded ↔ Ersetzt, with a replacement ID.
  • In Progress ↔ Teilweise: implementation has started or is partial.
  • Unknown priority: To confirm ↔ Zu bestätigen.
Evidence and review

Proposals stay distinguishable from facts.

  • Proposed NFR thresholds remain labelled in Requirements Notes until confirmed.
  • Review/conflict notes are separate from delivery statuses.
  • Reviewed now means review completed, awaiting approval, in UC and TC guidance.
  • TC promotions require evidence; material changes return to Draft unless renewed evidence supports another status.
Verification: vocabulary and update contracts reviewed. The German TC exercise confirmed status demotion and language preservation; no full requirements-translation workflow was run.
